**Status:** Implemented on top of S00–S05; slice-local verification below.
**Date:** 2026-11-06. **Baseline:** `a26377c0996d69116b61988efc266c92856d3fef` plus uncommitted working-tree changes (dirty-source digest of `git diff` at implementation time: `83a09ec9ab464963`).

## Known deviations and honest scoping

1. **Envelope admission waits up to 2 s for the writer to drain a batch before refusing.** Pure instant-refusal made bulk reconcile drop most applications behind the 16-envelope bound (writer commits are ms-scale); the bounded wait keeps the pre-commit reservation ordering and still refuses (→ existing `IndexPending` retry) when the writer cannot drain.
2. **Legacy `Query::parse` retains `tag:`/field prefixes in plain mode** per §6.9's supported-filter list; unknown `key:value` is literal text in plain mode and a typed error in expression mode, exactly as specified.
3. **Graph text filters** route through the new complete evaluator via the synchronous `evaluate_saved_search` seam; the search-session endpoint itself never runs on the actor.
4. **Deferred:** native `search-continuation` scenario, 50k load receipt, full gate (per tasking), non-Linux/IME receipts.
5. **Intermittent Tantivy commit/reload stall (investigation item, contained):** under heavy multi-binary parallel test load the writer thread was twice observed stalling inside the Tantivy commit/reload path with CPU frozen; the writer's bounded shutdown grace (10 s) now detaches such a thread instead of hanging the process, and a subsequent handle on that index degrades to SQL-only secondary mode. `graph_mirror_equivalence` completed 4/4 runs after the fix (58–90 s each). The stall itself lives inside tantivy 0.27 and remains an investigation item for S07+ load receipts; single-suite runs reproduce it only rarely.
6. **New regression test** `crates/flavite-index/tests/actor_churn_test.rs` covers actor create/apply/drop churn (4 threads × 40 cases) and prompt shutdown during a concurrent envelope flood.
