# RFC-0006 S08 — Durable saved-note replacement, partial results and restart

**Status:** Implemented on top of S00–S07; slice-local verification below.
**Date:** 2026-11-06. **Baseline:** `84ce963` (S07) plus this slice's
working-tree changes; dirty-source digest recorded at implementation time.
**Review:** the S08 implementation is part of the S00–S08 review report
(`RFC0006-S07-review.md` covers S00–S07; this receipt covers S08).
**Deferred (recorded honestly, per §11):** the native
`vault-saved-replace` workbench-visual run (Xvfb/OCR), the 50k/2 GiB load
receipts, Windows/macOS native displacement receipts, and the full release
gate (`just ci-gate`, coverage, non-Linux platforms). On this Linux host
the retained-replacement implementation uses `renameat2(RENAME_EXCHANGE)`
(rustix, pin verified in the lock); macOS/Windows are `Unsupported` by
design until their platform tests run — never an emulated overwrite.

## What landed

| Module | Change |
|---|---|
| `flavite-fs` | New retained-replacement surface (`Fs::replace_preserving_displaced`, `exchange`, `supports_retained_replace`, `DisplacedObject`), with a generic composite algorithm over the trait surface. MemFs implements atomic exchange with durable/volatile modeling; FaultFs orchestrates the algorithm through its own injected methods (every sub-step fault-injectable); OsFs uses `renameat2(RENAME_EXCHANGE)` on Linux and returns `Unsupported` elsewhere. `FsError::BaseMismatch`/`RetainedReplace` typed variants. |
| `flavite-vault/src/save.rs` | Normal saves of existing notes route through the shared retained-replacement primitive; the legacy `rename_replace` overwrite path is gone. Prior bytes are history-snapshotted before effect; the actual displaced object is archived durably (`HistoryReason::Displaced`) before the sibling staging dir is retired; a displaced mismatch (external writer raced at the exchange) is reported as `ReplacedDisplacedConflict` with the racing bytes preserved — never a false Saved. 10k process-crash/power-loss schedules still leave old-or-new complete bytes. |
| `flavite-vault/src/source_leases.rs` (new) | Non-replacing per-note lease registry (`Edit`/`Save`/`Rename`/`Replace`), all-or-none multi-source acquisition in ascending native-key order, stale-release no-op. Session refuses Save/Edit/Rename on a leased source with `replacement-in-progress`. |
| `flavite-vault/src/operation_key.rs` (new, moved out of `replace/`) | Device-local 256-bit operation key in the OS data dir (no-clobber, fsynced, 0600) — outside the vault, never printed. `replace/auth.rs` is now a pure re-export shim so the replacement module stays std::fs-free. |
| `flavite-vault/src/private_state.rs` (new) | Atomic private-data-dir file primitives (temp+rename+sync) shared by the key store and the high-water head. |
| `flavite-vault/src/replace/log.rs` (new) | Authenticated append-only per-item log: length-prefixed frames, keyed BLAKE3 chain (genesis → previous authenticator), private high-water head in the OS data dir; chain + head verified on open; tamper/rollback/quarantine typed (never guessed). |
| `flavite-vault/src/replace/coordinator.rs` (new) | Job state machine: per-item `IntentDurable` before any effect, actor-mediated retained replacement + index upsert, terminal per-item records; per-item outcomes Saved/IndexPending/AppliedConflict/Stale/Unsupported/NeedsRecovery/SatisfiedUnattributed; cancel stops admission of the next item (finishing an in-flight item); idempotent receipts; JobTotals derived from item effects. |
| Session | `ReplaceApply/ReplaceCancel/ReplaceResume/ReplaceJobStatus` commands; one active apply per vault; selection frozen on first Apply (SelectionLocked otherwise); idempotent replay returns the stored receipt; worker loop opens/verifies theJobLog; `recover_replace_jobs` at Session construction classifies intents against durable disk hashes (before-hash=not applied, after-hash=satisfied/never re-overwritten, neither=divergence) and never auto-continues. |
| Actor | `ApplyReplaceItem` message: contained read, exact base hash check, retained replacement, durable archival of the actual displaced object, index upsert; `IndexPending` when only cache repair remains; `OpStoreWriteReplace`/`OpStoreListDir` bounded ops. |
| API | `replace.apply/cancel/resume/job_status` facade commands (apply/resume/cancel are WriteNotes; job_status ReadNotes), idempotency keys, JSON projections; read-only vaults reject apply through the write gate. |
| CLI | `replace` subcommand (preview/select/apply with inline preview+select/status/cancel/resume) and `doctor` operation inventory (manifest ok/selection/records/head/quarantine), never printing key material. |
| UI | Replace tab gains Apply/Cancel/Resume controls and live job phase/totals; new `host/operations.rs` + `views/operations.rs` aggregate the live job inventory (refresh clamp 250 ms per NFR-17). |
| Gates/tests | `scripts/check-workbench-contracts.sh S08` (147 cumulative gates incl. the spec-mandated `assert_absent` invocations), xtask `s08_gate` negative fixtures, `retained_replace` (Fs), `replace_fault` (8), `replace_leases` (2), API `replace_apply` (5), UI `replace_operations` (2), CLI `operations_cli` (2). |

## Known deviations and honest scoping

1. **Native scenario deferred**: `scripts/tests/workbench/vault_saved_replace.py` is not executed in this slice (requires Xvfb/OCR; same precedent as S06/S07). The receipt marks the pixel/AT probe `incomplete`.
2. **macOS/Windows retention**: `supports_retained_replace` is `false` (honest Unsupported) until platform contract tests run; the UI/CLI refuse retained replacement on those platforms instead of weakening the save.
3. **Open clean buffers**: after a job replaces a note that is open and Clean, the existing watcher/reconcile external-change path adopts the new bytes (the view observes the same output). The separate non-coalescing Undo boundary for that adoption is not synthesized; this is recorded as a deviation from the literal D-11 wording for open-buffer adoption.
4. **Revert, drafts, GC, retained-job retention UI, export/quarantine flows are S09/S11** — not exposed here.
5. `replace.forget` is not registered in S08 (S11).
6. Full RFC-0006 conformance (S00–S11, AC-1–26 incl. all native/platform receipts) is not claimed; see §10 of the RFC.

## Exit criteria mapping (S08)

- AC-11 (stale/grant guards): per-item re-read + base hash guard; Stale/Denied final for the sealed plan; zero effects on refusal — tested.
- AC-12 (replay/crash idempotency): identical apply replays the same receipt; restart classification then Resume; never double-applies (after-hash satisfied never re-overwritten) — tested.
- AC-13 (retained actual bytes): external race retains both our output and the displaced bytes; conflict is a distinct outcome — tested (Fs + vault + API).
- AC-14 (index-pending repair): source outcome durable; cache repair separate; no repeated overwrite — tested via `IndexPending` mapping in actor flow.
- AC-16 (quota/cancel): cancel stops next-item admission; per-item terminal counts derived — tested (cancel + exact counts).
- AC-17 (boundaries/capabilities): contained reads, id validation, read-only gate, lease refusal — tested.
- AC-18 (migration/quarantine): authenticated log tamper/head mismatch quarantine; unknown jobs typed — tested.
- AC-22 (ownership): source-search closure untouched; replace module has no raw std::fs (gates); coordinator off UI thread (gates).
- FR-10/11/12: partial results name each outcome; durable operation identity idempotent; conflict/uncertainty never presented as Saved — tested.
