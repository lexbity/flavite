# RFC-0006 S09 — Explicit draft application, recovery lineage and guarded Revert

**Status:** Implemented on top of S00–S08; slice-local verification below.
**Date:** 2026-11-06. **Baseline:** `a961ac3` (S08) plus this slice's
working-tree changes; dirty-source digest recorded at implementation time.
**Review:** the S09 implementation is part of the S00–S09 review report;
this receipt covers S09.
**Deferred (recorded honestly, per §11):** the native
`draft-replace-revert` workbench-visual run (Xvfb/OCR), the 50k/2 GiB
draft/revert load receipts, Windows/macOS native displacement receipts, and
the full release gate. On this Linux host the retained-replacement
implementation remains `renameat2(RENAME_EXCHANGE)` (rustix); macOS/Windows
are `Unsupported` by design until their platform tests run.

## Known deviations and honest scoping

1. **Native scenario deferred**: `scripts/tests/workbench/draft_replace_revert.py`
   is scaffolded but not executed in this slice (requires Xvfb/OCR; same
   precedent as S06–S08). The receipt marks the pixel/AT probe `incomplete`.
2. **Revert selection granularity**: `replace.revert` applies to all
   eligible (applied) items; per-item deselect before revert is not
   exposed (D-11's "applies only selected verified items" is satisfied by
   the per-item guards and per-item outcomes, but there is no interactive
   pre-selection list — recorded as a deviation).
3. **macOS/Windows retention**: `supports_retained_replace` remains `false`
   on those platforms; Revert is refused with `Unsupported` there, with
   read/preview still available.
4. **`satisfied_unattributed`/`reverted` for a draft whose ordinary
   autosave landed at the after state**: such items revert through the disk
   path (state Clean at after-hash), reported as `reverted` — documented in
   `revert_draft_item`.
5. Full RFC-0006 conformance (S00–S11, AC-1–26 incl. all native/platform
   receipts) is not claimed; see §10 of the RFC.

## Exit criteria mapping (S09)

- AC-11 (stale/grant guards): draft apply requires exact revision/hash/
  state/disk-base; revert guards skip later typing/Undo-to-identical/external
  writes — tested.
- AC-12 (replay/crash idempotency): duplicate apply/revert replay the same
  receipt; restart classification never re-overwrites — tested (see also
  S08's crash schedules).
- AC-15 (draft lineage/Revert): checkpoint-before-terminal, no forced save,
  guarded Revert with mixed outcomes, restart recovery — tested.
- AC-18 (migration/quarantine): old plans without draft fields remain
  readable (serde defaults); authenticated revert records extend the same
  chain — tested.
- FR-1/2/3/9/10/11/13: draft opt-in, AppliedDraft distinct from Saved,
  Revert as a new action epoch with per-note outcomes — tested.
- AC-22 (ownership): source-search closure untouched; replace module still
  std::fs-free; hosts handle `.session(`/`std::fs`/global-undo (gates).
